# Debugging Omanosaura

Match the symptom, apply the fix. Most production breakage here has been config,
not code.

## Login fails / `auth/unauthorized-domain`

Every domain the app is served on must be in Firebase authorized domains. Check
and fix with the service account (Identity Toolkit admin API):

```bash
NODE_OPTIONS=--dns-result-order=ipv4first node --env-file=.env -e "
const {initializeApp,cert}=require('firebase-admin/app');
const key=JSON.parse(Buffer.from(process.env.FIREBASE_SERVICE_ACCOUNT,'base64').toString());
const app=initializeApp({credential:cert(key)});
(async()=>{ const t=(await app.options.credential.getAccessToken()).access_token;
  const r=await fetch('https://identitytoolkit.googleapis.com/admin/v2/projects/'+key.project_id+'/config',{headers:{Authorization:'Bearer '+t}});
  console.log((await r.json()).authorizedDomains); })();
"
```

PATCH the same endpoint with `?updateMask=authorizedDomains` and the full domain
array to add one. **Firebase Dynamic Links deprecation does NOT affect this app** —
it only breaks mobile-app email links and Cordova web OAuth; our web popup +
email-link auth still work and remain free.

Auth flow: client signs in (`src/components/layout/auth-client.ts`) → POST
`/api/auth/session` mints an HttpOnly session cookie → `src/lib/auth.ts` verifies
it server-side. The navbar reads `/api/auth/me` client-side.

## `ETIMEDOUT` reaching Google or Neon from the CLI

This machine's IPv6 route to Google/Neon is dead. Prefix the command with
`NODE_OPTIONS=--dns-result-order=ipv4first` and retry once — the token endpoint
sometimes needs a second attempt.

## Database errors

- App uses the **pooled** `DATABASE_URL`; migrations/dumps use **direct**
  `DIRECT_DATABASE_URL`. Using pooled for a migration fails in confusing ways
  (`prepared statement already exists`, phantom "relation does not exist").
- Local dev is Docker Postgres on `:5433`, not Neon: `docker start omanosaura-dev-db`.
- `src/lib/db.ts` chooses the Neon vs pg adapter by hostname; a wrong
  `DATABASE_URL` host silently uses the wrong driver.
- "Failed to collect page data" during build is usually a Neon cold start —
  rerun the build.

## Thawani payments not completing

Fulfillment is **webhook-first** (`src/app/api/webhooks/thawani/route.ts`,
HMAC-verified with `THAWANI_WEBHOOK_SECRET`), with the success redirect
(`/api/purchase/success/[id]`) and a daily cron
(`/api/cron/reconcile-purchases`) as backups. All three are idempotent via
`src/lib/fulfill.ts`. If a paid purchase stays `complete=false`:
- Confirm the webhook URL + secret are set in the Thawani merchant portal.
- Check the session status via `thawani.getSessionByClientReference(purchaseId)`.
- The reconcile cron sweeps card purchases `<7 days` old — it self-heals.
- Remember Thawani is on **UAT** until the keys are swapped to production.

## Emails not sending

SMTP is Brevo, env-driven (`src/lib/email.ts`): `SMTP_HOST`, `SMTP_PORT`,
`EMAIL_USERNAME`, `EMAIL_PASSWORD`, `EMAIL_FROM`. Verify creds:

```bash
NODE_OPTIONS=--dns-result-order=ipv4first node --env-file=.env -e "
const n=require('nodemailer');
n.createTransport({host:process.env.SMTP_HOST,port:+process.env.SMTP_PORT,secure:false,
auth:{user:process.env.EMAIL_USERNAME,pass:process.env.EMAIL_PASSWORD}}).verify()
.then(()=>console.log('SMTP OK')).catch(e=>console.error(e.message));"
```

535 = bad credentials. The `EMAIL_FROM` sender domain must be verified in Brevo.
Sends run in `after()` so they never block a response — check function logs, not
the request, for failures.

## Images not loading

Blog images are self-hosted in `public/blog-media/` → `/blog-media/...`. Product
photos are free-text URLs; `next.config.ts` allows any https host, and
`src/components/safe-image.tsx` falls back for empty/GIF URLs. A broken product
image means a dead source URL in the DB — fix the row.

## Build / deploy failures

- `npm run build` locally first; it runs `prisma generate` then `next build`.
- Missing `@/generated/prisma` = `prisma generate` didn't run; it's gitignored on
  purpose and regenerated by the build.
- `useSearchParams() should be wrapped in a suspense boundary` = a client
  component using search params rendered on a static page; wrap it in `<Suspense>`.
- Vercel build logs: MCP `get_deployment_build_logs` (`errorsOnly: true`) or
  `npx vercel inspect <url> --logs`.
